    What's real here, and what is not
    
    
      
  • Real: the agent genuinely executes the code under test (in your browser), reads which tests fail, generates patch candidates, re-runs the whole suite on each one, and keeps the best-scoring few (a beam search) for the next round. Loops are guarded so an infinite-loop patch is rejected instead of freezing the page.
    • 
      
  • Not an LLM: patch candidates come from simple mutation rules (flip < and <=, + and -, && and ||, nudge a number by one, swap min and max). That is the idea behind automated program repair tools such as GenProg. It cannot invent new code, so the last sample is genuinely unfixable for it and it reports failure.
    • 
      
  • Passing the tests does not prove the code is correct. A patch can satisfy a weak suite and still be wrong, which is a known weakness of test-driven repair. The test lists are short on purpose so you can read them.
