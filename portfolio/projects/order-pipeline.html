Real-Time Event-Driven Order Pipeline

A production-style e-commerce order flow — validate → reserve inventory → charge payment → ship → notify — decoupled through a message queue. Each stage is an independent consumer with its own retry policy and a dead-letter queue for anything that fails permanently.

Topology — Producer → Queue → Consumers → DLQ

Each consumer pulls from its own topic/partition. A failed message is retried with backoff up to a limit, then routed to the dead-letter queue instead of blocking the pipeline — so one bad order never stalls the rest of the stream.

# Each stage consumes its own topic and republishes to the next,
# so stages scale and fail independently.

MAX_RETRIES = 3

def process_with_retry(consumer, handler, next_topic, dlq_topic):
    for msg in consumer:
        attempt = msg.headers.get("retry_count", 0)
        try:
            result = handler(msg.value)
            producer.send(next_topic, value=result)
            consumer.commit(msg)
        except TransientError as e:
            if attempt >= MAX_RETRIES:
                producer.send(dlq_topic, value=msg.value,
                               headers={"error": str(e), "stage": handler.__name__})
                consumer.commit(msg)
            else:
                backoff = (2 ** attempt) * 0.5
                producer.send(consumer.topic, value=msg.value,
                               headers={"retry_count": attempt + 1},
                               delay=backoff)
                consumer.commit(msg)

def reserve_inventory(order):
    if not inventory.reserve(order["sku"], order["qty"]):
        raise TransientError("insufficient_stock")
    return {**order, "reserved": True}

def charge_payment(order):
    charge = payments.charge(order["payment_token"], order["total"])
    if not charge.success:
        raise TransientError("card_declined")
    return {**order, "charge_id": charge.id}
