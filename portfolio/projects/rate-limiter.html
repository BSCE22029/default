Node Buckets (Local View, Synced via Shared Store)

Each node keeps a local cache of the bucket state and reconciles it against a shared atomic store (e.g. Redis EVAL with a Lua script) on every request — this is what makes the limit correct even when requests land on different nodes behind a load balancer.

Atomic Token Bucket (Redis Lua Script)
-- rate_limiter.lua — Muhammad Moiz Ahmad
-- Runs atomically inside Redis so concurrent requests across nodes
-- never race on the same bucket (EVAL is single-threaded in Redis).

local key           = KEYS[1]
local capacity      = tonumber(ARGV[1])
local refill_rate   = tonumber(ARGV[2])
local now           = tonumber(ARGV[3])

local bucket = redis.call("HMGET", key, "tokens", "ts")
local tokens  = tonumber(bucket[1]) or capacity
local last_ts = tonumber(bucket[2]) or now

-- refill based on elapsed time since last request
local elapsed = math.max(0, now - last_ts)
tokens = math.min(capacity, tokens + elapsed * refill_rate)

local allowed = tokens >= 1
if allowed then tokens = tokens - 1 end

redis.call("HMSET", key, "tokens", tokens, "ts", now)
redis.call("EXPIRE", key, 60)

return { allowed and 1 or 0, math.floor(tokens) }
