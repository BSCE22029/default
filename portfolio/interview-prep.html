💬 Interview Questions
Why Conv1D instead of an RNN or LSTM for gesture classification?Medium▼
Gesture data is a short, fixed-length time series (119 frames, ~1.2 seconds). Conv1D is faster, needs less memory, and doesn't have vanishing gradient issues. LSTMs need sequential state — expensive on microcontrollers. For a bounded window like this, Conv1D gets 97%+ while staying under 20KB. I only use RNNs when context window is variable or very long.
Explain INT8 quantization. What's the trade-off?Medium▼
What it does: replaces 32-bit float weights with 8-bit integers using a scale factor and zero point. float = (int8 − zero_point) × scale. Reduces model size 4×, speeds up inference 2–4× on integer-only hardware.

Trade-off: ~0.5–2% accuracy drop. Fixed with representative dataset calibration — I passed 200 training samples to the converter so it could pick optimal scale factors per layer.
How did you collect training data? How many samples?Easy▼
Collected 200+ samples per gesture class (6 classes = 1200+ samples) using a simple Arduino sketch that buffers 119 IMU frames at 119Hz and logs them over serial. Captured from multiple people to reduce person-specific bias. Augmented by adding Gaussian noise and slight time shifts to each sample during preprocessing.
What's the TFLite for Microcontrollers workflow end to end?Hard▼
1. Train in Keras (full float32). 2. Convert with TFLiteConverter + TFLITE_BUILTINS_INT8 — needs a representative dataset for calibration. 3. Save as .tflite. 4. Convert to C byte array: xxd -i model.tflite > model.h. 5. On Arduino: GetModel() → AllOpsResolver → AllocateTensors() → Invoke(). The tensor arena (static RAM buffer) must be sized correctly — too small = crash, too big = OOM.

I implemented a 4×4 systolic array of Processing Elements in Verilog HDL where each PE computes a multiply-accumulate operation. Data flows left to right, weights flow top to bottom — this is the same architecture Google uses in their TPUs. Running at 50MHz on Xilinx Artix-7, it achieves 12.8 GOPS for INT8 matrix multiply, which is the bottleneck operation in neural network inference.
💬 Interview Questions
What is a systolic array and why is it efficient for matrix multiply?Medium▼
A systolic array is a grid of simple processing elements that pass data between neighbors every clock cycle — like a heartbeat (systole). For matrix multiply A×B: row elements of A flow right across rows of PEs; column elements of B flow down columns. Each PE does acc += a × b every cycle. Why efficient: data reuse — each value passes through N PEs before leaving, so we get N MACs per load instead of 1. No global memory bus bottleneck.
How does your design handle the difference between training precision (FP32) and inference (INT8)?Hard▼
Training stays in FP32 on a GPU — the hardware accelerator only does inference. Before deployment, weights are quantized: w_int8 = round(w_float32 / scale) where scale is computed per-layer during calibration. The accumulator is INT32 (32-bit) to avoid overflow from multiplying two INT8 values — max product is 127×127=16129, which fits in INT32. After accumulation, we clamp back to INT8 with the bias and activation.
What is the difference between ASIC, FPGA, and GPU for neural network inference?Medium▼
GPU: Flexible, massively parallel, high bandwidth but high power (50–300W). Best for training and large-batch cloud inference.
FPGA: Reconfigurable, medium power (5–25W), good for custom precision and streaming data. My accelerator runs here. Latency is deterministic — critical for real-time systems.
ASIC: Fixed function (like Google TPU, Apple Neural Engine). Highest TOPS/W but zero flexibility. Can't reprogram after fabrication.

This uses an autoencoder — trained only on normal machine vibration data — to detect faults without ever seeing a labeled fault example. The idea is: the autoencoder learns to reconstruct normal patterns perfectly, so when a fault occurs, the reconstruction error spikes above a threshold. Running on ESP32 at 12ms latency, it catches bearing damage, rotor imbalance, and shaft misalignment with 98.2% detection rate and under 1% false positives.
💬 Interview Questions
Why use an autoencoder for anomaly detection instead of a classifier?Medium▼
A classifier needs labeled examples of every fault type — but in industry you rarely have enough fault data, and new fault types appear unexpectedly. An autoencoder only needs normal data to train. It learns what normal looks like. When something abnormal happens, it can't reconstruct it well, so reconstruction error = MSE(input, decoded) spikes above threshold. This is called unsupervised anomaly detection — no fault labels needed.
How did you pick the anomaly threshold (0.45)? What if it's wrong?Hard▼
I computed reconstruction errors on a validation set of normal data and set the threshold at mean + 3σ (three standard deviations above average normal error). This catches 99.7% of genuine anomalies in a Gaussian distribution. You can also use ROC curve analysis to pick the threshold that maximizes F1 score on your test set. The trade-off: lower threshold = more false alarms; higher threshold = missed faults. In safety-critical systems you bias toward more false alarms.
What features did you extract from the vibration signal?Medium▼
Time-domain: RMS (overall vibration level), crest factor (peak/RMS — high in bearing faults), kurtosis (impulsiveness — very sensitive to early bearing damage), skewness. Frequency-domain: THD (total harmonic distortion — catches misalignment harmonics), spectral entropy. The autoencoder operates on the raw windowed time series (128 samples × 3 axes), but these features are the interpretable signals I used to validate it.

I built a wake word detector using the same architecture as Alexa or Google Assistant — MFCC feature extraction feeding a depthwise separable CNN. The audio pipeline runs entirely on STM32F4: 16kHz PCM → pre-emphasis → 25ms STFT frames with 10ms hop → 40-band mel filterbank → DCT → 40×49 spectrogram → DS-CNN inference in 8ms. The DS-CNN is 9× cheaper than a standard CNN with comparable accuracy because depthwise convolutions factorize the computation.
💬 Interview Questions
Explain MFCC step by step. Why Mel scale instead of linear frequency?Hard▼
1. Pre-emphasis: boost high freqs with y[n] = x[n] − 0.97×x[n−1] to compensate for vocal tract roll-off.
2. Frame + window: split into 25ms frames with 10ms hop, apply Hamming window to reduce spectral leakage.
3. FFT: compute magnitude spectrum.
4. Mel filterbank: apply 40 triangular filters spaced on the Mel scale (mel = 2595 × log(1 + f/700)). Human hearing is logarithmic — we hear differences between 100Hz and 200Hz much more clearly than between 8000Hz and 8100Hz.
5. Log + DCT: take log (compresses dynamic range) then DCT (decorrelates features). Result: 40 MFCC coefficients per frame.
What is a depthwise separable convolution and why is it useful on embedded?Medium▼
A standard Conv2D with F filters of size K×K×C costs K²×C×F multiplications per output. A depthwise separable conv splits this into:
• Depthwise conv: one K×K filter per input channel — cost K²×C
• Pointwise conv: 1×1 convolution to mix channels — cost C×F
Total: K²×C + C×F = C(K² + F) vs K²×C×F. For K=3, F=32: 9× cheaper. Same expressiveness, 9× fewer MACs. Critical for MCUs with no FPU.
How do you handle the sliding window — does every 1 second of audio get classified?Medium▼
Yes, continuously. I use a ring buffer of audio frames. Every 10ms (1 hop), a new frame is added and the oldest is dropped — so the spectrogram always covers the latest ~490ms. Inference runs every 10ms. To avoid false positives from a single frame, I require 3 consecutive detections above threshold before triggering the wake event. This adds 30ms latency but eliminates spurious triggers from noise or partial words.

UART Transceiver
Verilog HDLSerial Protocol8N1
Embedded
30-Second Pitch
I implemented a full UART transceiver in Verilog — 8 data bits, configurable parity, 1 stop bit — simulated in Vivado. The transmitter uses a shift register clocked at baud rate (CLKS_PER_BIT = CLK_FREQ / BAUD_RATE). The receiver samples at the midpoint of each bit to avoid edge metastability. I verified it against a logic analyzer simulation to confirm correct frame timing.
💬 Interview Questions
Walk me through a UART frame. What are the start and stop bits for?Easy▼
Idle line is HIGH (logic 1). A frame starts with a start bit (logic 0) — this falling edge wakes the receiver. Then 8 data bits LSB first, then optional parity, then 1+ stop bits (logic 1) to guarantee the line returns to idle before the next byte. The stop bit also gives the receiver time to process the byte. Without start bit: no way to know when a byte begins. Without stop bit: next start bit could be mistaken as a data bit.
UART vs SPI vs I2C — when do you use each?Medium▼
UART: 2-wire async, no clock, point-to-point. Use for debug consoles, GPS modules, Bluetooth modules. Simple but slow (115200 baud max typical).
SPI: 4-wire sync, full duplex, master/slave. Use for SD cards, displays, ADCs needing high speed (up to 80MHz). One CS pin per slave.
I2C: 2-wire sync, multi-device on same bus (address-based). Use for sensors (IMU, temp, OLED) where speed isn't critical (max ~3.4MHz). Only 2 wires but needs pull-ups.
How does your Verilog receiver avoid sampling at the wrong edge of a bit?Hard▼
When the start bit is detected (falling edge), the receiver waits for 1.5 × CLKS_PER_BIT before sampling the first data bit — this puts the sample at the midpoint of the first data bit, away from the edges where transitions occur. For each subsequent bit, it waits exactly CLKS_PER_BIT more. This tolerates up to ±50% clock skew between TX and RX baud rate generators.

PWM Motor Controller
Verilog HDLArduinoMotor Control
Embedded
30-Second Pitch
I implemented PWM generation in Verilog using a counter/comparator approach: a free-running counter resets at PERIOD = CLK_FREQ / PWM_FREQ, and the output is HIGH while the counter is below the threshold (threshold = PERIOD × duty_cycle / 256). This is the same technique used in microcontroller timer peripherals. The demo shows real-time waveform, motor RPM proportional to duty cycle, and LED brightness dimming.
💬 Interview Questions
What PWM frequency should you use for a DC motor? For an LED? Why do they differ?Medium▼
DC motor: 1kHz–20kHz. Lower = audible whine from motor coils. Higher = switching losses increase in the H-bridge MOSFETs. 5–20kHz is the sweet spot — above human hearing, below excessive switching loss.
LED: >50Hz to avoid flicker visible to the eye (persistence of vision). 1kHz is standard. Higher frequencies are fine since LEDs switch nearly instantaneously.
Servo motors: fixed 50Hz — the pulse width (1–2ms) encodes angle, not brightness.
What is dead time in an H-bridge and why is it needed?Hard▼
An H-bridge has high-side and low-side MOSFETs on each leg. If both turn on simultaneously even for nanoseconds, you get shoot-through — a direct short from VCC to GND, instantly destroying the transistors. Dead time is a short delay (50–500ns) inserted between turning off one switch and turning on the complementary switch, giving the off-transistor time to fully close before the other opens. In Verilog: insert a state machine delay in the gate drive signals.
⚠ Gotcha Questions

RISC-V Pipelined Processor
Verilog HDLRV32I5-Stage Pipeline
Embedded
30-Second Pitch
I implemented a 5-stage pipelined RISC-V processor (RV32I ISA) in Verilog: Fetch, Decode, Execute, Memory, Writeback. The hazard unit detects RAW hazards and inserts data forwarding paths from EX/MEM stages back to the ALU inputs. Load-use hazards stall the pipeline for one cycle. Branch instructions flush the pipeline on misprediction. Verified with a custom assembly test suite in simulation.
💬 Interview Questions
What is a data hazard? How does forwarding solve it?Medium▼
A RAW (Read After Write) hazard: instruction B needs a value that instruction A is still computing. Example: ADD x1, x2, x3 followed immediately by SUB x4, x1, x5. Without forwarding, B would read stale x1.
Forwarding: instead of waiting for A's result to be written to the register file and read back, wire the ALU output directly to the next instruction's ALU input. The hazard unit detects that B's source register matches A's destination register and enables the forward MUX. Eliminates the stall for EX-EX and MEM-EX hazards.
Why can't you forward from a load instruction to the immediately following instruction?Hard▼
A LW (load word) instruction reads from memory in the MEM stage, but the next instruction needs that value in its EX stage — which happens simultaneously. You can't forward a value that hasn't been read yet. This is the load-use hazard. The only solution is to stall: insert a NOP bubble between them, delaying the dependent instruction by one cycle. The compiler can reorder instructions (load scheduling) to fill that slot with an independent instruction, avoiding the stall.
What is a control hazard and how does branch prediction help?Medium▼
When a branch is fetched, the CPU doesn't know the target address until the EX stage (2 cycles later). In those 2 cycles, it has fetched the wrong instructions. Static prediction: always predict not taken (flush on taken branch — 2-cycle penalty). Branch prediction: use a branch history table to predict taken/not-taken. If correct: no penalty. If wrong: flush 2 instructions (2 × 1 cycle = 2 cycle penalty). Modern CPUs predict 99%+ of branches correctly.

I implemented a 4-bit ALU in Verilog supporting 8 operations — ADD, SUB, AND, OR, XOR, NOT, SHL, SHR — with all four CPU status flags: Zero, Carry, Negative, and Overflow. The carry is implemented using a 4-bit ripple carry adder with carry propagation. 💬 Interview Questions
What is the difference between signed overflow and unsigned carry?Hard▼
Carry (unsigned): the result doesn't fit in N bits. In 4-bit: 15+1=16, which overflows unsigned range [0,15]. Carry flag = 1.
Overflow (signed): adding two same-sign numbers gives a different-sign result. In 4-bit 2's complement: 7+1=8 but 8 is -8 in 4-bit signed — this is overflow. Detection: OVF = (a[3] == b[3]) && (result[3] != a[3]). You can have carry without overflow (unsigned overflow but result is still valid signed) and overflow without carry.
How does 2's complement subtraction work in hardware?Medium▼
Instead of having a separate subtractor circuit, A - B = A + (~B) + 1. The 2's complement of B is bitwise-NOT(B) plus 1. In an adder circuit: invert B using XOR gates (controlled by a subtract signal), and force carry-in to 1. So one adder circuit handles both ADD and SUB by toggling the subtract control line — hardware is shared, area is halved.

Multiple companies sign up and get completely isolated data through PostgreSQL Row-Level Security policies: every query is automatically filtered by org_id. 💬 Interview Questions
How did you implement multi-tenancy? What is Row-Level Security?Hard▼
Multi-tenancy means multiple customers share the same database but can never see each other's data. I used PostgreSQL Row-Level Security (RLS): CREATE POLICY tenant_isolation ON leads USING (org_id = auth.jwt()->>'org_id'). Every SQL query automatically gets a WHERE clause appended by the database engine — it's enforced at the DB level, not application code. Even if I have a bug in my React code that sends the wrong org_id, the database rejects the query. This is much safer than application-level filtering.
How does Supabase Realtime work? What's happening under the hood?Medium▼
Supabase Realtime uses PostgreSQL's logical replication (WAL — Write Ahead Log). When a row is inserted/updated/deleted, Postgres writes it to the WAL. Supabase's Realtime server reads the WAL via a replication slot and broadcasts changes over WebSockets to subscribed clients. On the client: supabase.channel('leads').on('postgres_changes', {...}).subscribe(). The client only receives changes that match the RLS policy — tenant isolation is preserved in real time too.
How did you handle auth? What's the difference between JWT and session auth?Medium▼
I used Supabase Auth which issues JWTs (JSON Web Tokens). A JWT is a stateless, self-contained token: header.payload.signature. The server doesn't store session state — it just verifies the signature with the secret key. The payload contains the user's ID and org_id, which RLS policies read directly.
vs Sessions: session auth stores a session ID in a DB and checks it on every request — stateful, requires DB lookup. JWTs are faster (no DB lookup) but can't be revoked before expiry. I use short-lived access tokens (1h) + refresh tokens to mitigate this.

💬 Interview Questions
What is the difference between authentication and authorization?Easy▼
Authentication (AuthN): "Are you who you say you are?" — verifying identity. Login with email+password, Google OAuth, biometric. Result: a JWT or session token.
Authorization (AuthZ): "Are you allowed to do this?" — checking permissions. "Can this user delete this resource?" Role-based: admin can delete, user cannot. Resource-based: user can only delete their own posts.

Common mistake: checking authentication but not authorization. A logged-in user shouldn't be able to delete other users' posts — that's an authorization check.
Why bcrypt for password hashing? Why not SHA256?Medium▼
SHA256 is designed to be fast — an attacker can compute billions of hashes per second on a GPU to crack passwords by brute force. bcrypt is intentionally slow (controlled by cost factor: cost=12 means 2¹² iterations, ~250ms on modern hardware). It also automatically salts the password, making rainbow table attacks impossible. Even if two users have the same password, their hashes are different.
Argon2 is even better — won the Password Hashing Competition in 2015. I'd use Argon2id in production.
What are HTTP status codes 401 vs 403? When does each apply?Easy▼
401 Unauthorized: "You haven't authenticated yet (or your token is invalid/expired)." Send a new login request to get a token. Confusingly named — it's really "unauthenticated."
403 Forbidden: "You're authenticated but you don't have permission." You're logged in, but you're trying to access someone else's resource or an admin-only endpoint. No amount of re-authentication will help — you're just not allowed.

Pattern: API key missing → 401. API key valid but user is not admin → 403.

A CNN trained on MNIST achieving 98%+ accuracy. The architecture — Conv2D(32) → MaxPool → Conv2D(64) → MaxPool → Flatten → Dense(128) → Dropout(0.5) → Softmax(10) — uses convolutional layers to learn spatial features (edges, curves) before the dense classifier. 💬 Interview Questions
Why does a CNN work better than a fully connected network on images?Medium▼
Translation invariance: a dog in the top-left and a dog in the bottom-right should both be "dog." CNNs share weights (same kernel slides over entire image), so a feature detector is position-agnostic. A fully connected network has a separate weight for every pixel — it would have to independently learn "dog in every position."
Local connectivity: nearby pixels are strongly correlated (edges, textures). Convolution captures this with a small receptive field. FCNs treat every pixel independently — no spatial structure exploited.
Parameter efficiency: 3×3×32 kernel = 288 parameters. FC from 28×28 to 256 = 200,704 parameters.
What does dropout do, and why does 0.5 mean half the neurons, not half the weights?Medium▼
Dropout randomly sets neuron activations to zero during training (not the weights). With p=0.5, each neuron is zeroed out with 50% probability independently on each forward pass. This forces the network to not rely on any single neuron — it must learn redundant representations. Effect: acts like training an ensemble of 2^N different networks.
Important: during inference, dropout is disabled and outputs are scaled by (1-p) to keep the expected activation magnitude the same.

An animated visualizer covering four sorting algorithms with comparison/swap counters, adjustable speed, and full Python + C++ implementations. The key thing I can explain is: why Merge Sort is O(n log n) worst case but Quick Sort is O(n²) worst case — and yet Quick Sort is often faster in practice because of cache locality and smaller constant factors.
💬 Interview Questions
Why is Quick Sort usually faster than Merge Sort despite worse worst-case?Hard▼
Cache locality: Quick Sort partitions in-place, keeping data in the same memory region. CPU cache stays warm. Merge Sort allocates auxiliary arrays — more cache misses.
No auxiliary memory: Merge Sort needs O(n) extra space for merging. Quick Sort is O(log n) stack space (recursion depth).
Constant factors: Quick Sort's inner loop is simple — just comparisons and swaps on adjacent memory. The constant factor in the O(n log n) is small.
Worst case mitigation: randomized pivot or median-of-3 reduces probability of O(n²) to near zero in practice.
When would you use Insertion Sort over Merge Sort?Medium▼
For small arrays (n < 10–20). Insertion Sort's constant factor is tiny — it's just index comparisons and shifts in a tight loop. For 10 elements, Merge Sort's O(n log n) = 33 ops but its overhead (function calls, memory allocation) costs more than Insertion Sort's 100 comparisons. This is why Python's Timsort and Java's Arrays.sort use Insertion Sort for small subarrays within their Merge Sort implementation.
Also use for nearly-sorted data: Insertion Sort is O(n) best case — each element is already close to its final position.
